# er-research

이터널 리턴 스쿼드 랭크 경기를 직접 모아 집계하는 통계 웹 서비스입니다. 화면은 두 탭입니다.

- **조합 분석**: 내 실험체와 함께했을 때 성적이 좋았던 팀원 2명 조합을 S~D 티어로 보여줍니다.
- **전적 분석**: 닉네임을 넣으면 그 유저의 최근 20판을 DB 평균과 비교하고, Claude가 쓴 소견을 붙여 줍니다.

지인 공유용으로 운영하는 개인 포트폴리오 프로젝트입니다. 2026년 10월 기준으로 경기 5만 3천여 판, 참가자 기록 120만여 건을 모았습니다.

## 기능

### 조합 분석

- 내 실험체를 **실험체 / 무기 / 핵심 특성**(특성은 선택) 단위로 고릅니다.
- 같은 팀이었던 팀원 2명을 **실험체 / 무기** 단위로, 순서와 상관없이 묶어 집계합니다. 팀원 한 자리를 고정하고 나머지 한 자리만 볼 수도 있습니다.
- 지표는 판수, 1위율, TOP3율, 평균 RP(내 실험체의 MMR 변화), 평균 순위, 평균 팀 킬입니다.
- 티어 기준은 종합 점수가 기본이고 승률, RP, 판수로 바꿀 수 있습니다. 바꿔도 서버를 다시 부르지 않고 클라이언트에서 바로 다시 계산합니다.
- 고른 실험체 자체의 티어도 함께 보여줍니다.

### 전적 분석

- 최근 20판(코발트 제외)의 순위, 실험체별 성적, 시즌 모스트 3개를 보여줍니다.
- 같은 실험체·무기의 DB 평균과 비교해 다음을 판정합니다.
  - **팀 기여**: TK, 킬 점유율, 딜 점유율. 평균보다 뚜렷하게 높으면 딜 담당·킬 캐치 뱃지를 붙입니다.
  - **플레이 성향**: TOP3로 끝난 판의 시야 점수와 데스를 보고 시야 장악·생존왕 뱃지를 붙입니다.
  - **캐리·버스 판**: 딜량과 KDA가 모두 평균의 1.3배 이상이면 캐리, 모두 0.7배 이하면 버스로 봅니다. 해당 판을 눌러 팀 딜량과 함께 볼 수 있습니다.
- 위 통계를 Claude(Haiku)에 넘겨 5문단 소견을 스트리밍으로 받습니다.

## 풀어야 했던 문제

### 조합 승률 API가 없다

공식 Open API는 경기 단위 데이터만 줍니다. 그래서 수집기가 경기를 모아 SQLite에 쌓고, 페이지는 DB만 조회합니다.

```
Open API → 수집기(로컬, 백그라운드) → SQLite → 공개용 스냅샷 → Next.js (Vercel)
```

- 수집은 상위 1000위 유저에서 시작해, 그들의 최근 경기로, 다시 그 경기의 참가자로 넓혀 갑니다.
- 경기 ID를 기본 키로 써서 수집기를 몇 번 다시 시작해도 같은 경기가 두 번 쌓이지 않습니다.
- 배포본에는 원본 DB 대신 `pnpm snapshot`으로 만든 공개용 사본만 올립니다. 이 사본에서는 수집 대상 닉네임을 담은 테이블을 뺍니다.

### 호출 제한과 키 하나

API 키가 하나이고 호출 제한을 넘기면 키가 정지될 수 있습니다.

- 모든 호출이 서버 전역 큐를 지나며 1.1초 간격을 지키고, 429 응답에는 물러났다 다시 시도합니다.
- 전적 분석만은 요청 시점에 API를 부릅니다. 그래서 IP당 10분 3회 제한과 5분 메모리 캐시를 둡니다.
- 수집기가 도는 동안에는 키를 같이 쓰지 않도록 전적 분석을 꺼 둡니다.

### 표본이 적은 조합이 위로 올라온다

1판 100% 같은 기록이 S를 차지하지 않게 두 단계로 막습니다.

- **베이지안 보정**: 전체 평균 성적의 가상 경기 10판을 더한 값으로 점수를 냅니다.
- **판수 상한**: 백분위는 상대 순위라, 종합 등급에는 절대 상한을 둡니다. 3판 이하는 최고 B, 4~19판은 최고 A이고, S는 20판 이상만 받습니다.

### 실험체마다 기준이 다르다

딜러는 원래 딜량이 높고 탱커는 낮습니다. 그래서 전적 분석의 판정은 전체 평균이 아니라 **같은 실험체·무기의 DB 평균**과 비교합니다.

- 캐리·버스와 시야 판정은 TOP3로 끝난 판끼리 비교합니다. TOP3 판은 딜량이 평균의 1.6배쯤이라, 전체 평균과 비교하면 거의 모든 상위권 판이 캐리로 잡혔습니다.
- 표본이 모자란 실험체는 전체 평균에 TOP3 보정 배율을 곱해 대신 씁니다.

### 개인 정보와 약관

Open API 약관은 닉네임·userNum 같은 식별 정보의 노출을 금지합니다.

- 화면과 응답에는 집계 통계만 내보냅니다.
- 전적 분석의 닉네임은 URL이 아니라 POST body로만 받습니다.
- 닉네임과 조회 결과는 DB와 로그에 남기지 않고, Claude에도 보내지 않습니다.

## 기술 스택

| 분류 | 기술 |
|---|---|
| 프레임워크 | Next.js 16 (App Router), React 19 |
| 언어 | TypeScript (strict) |
| 스타일 | Tailwind CSS v4 |
| 클라이언트 상태 | Zustand (기준, 최소 판수, 정렬) · 실험체 선택은 URL 쿼리 |
| 서버 데이터 | TanStack Query (전적 분석은 NDJSON 스트림) |
| DB | SQLite (better-sqlite3), Drizzle ORM |
| AI | Anthropic SDK (Claude Haiku, 스트리밍) |
| 배포 | Vercel CLI |
| 린트 | ESLint 9, @stylistic/eslint-plugin |

## 실행

```bash
pnpm install
pnpm db:push        # 스키마 생성
pnpm load-meta      # 실험체·무기·특성 이름 불러오기
pnpm collect 300    # 경기 300판 수집 (두 번째 인자로 최대 실행 시간(시간) 지정 가능)
pnpm dev
```

`.env.local`에 키를 넣습니다. ER 키는 [Eternal Return Developers](https://developer.eternalreturn.io)에서 발급받습니다.

```
ER_API_KEY=발급받은_키
ANTHROPIC_API_KEY=발급받은_키   # 전적 분석 소견용
```

설계 결정의 배경은 [`docs/PLAN.md`](docs/PLAN.md)에, API의 필드와 주의사항은 [`docs/API_NOTES.md`](docs/API_NOTES.md)에 정리했습니다.
