# 기획서

## 목적

이터널 리턴은 3인 스쿼드 게임이다. **"내가 이 실험체를 할 때, 어떤 팀원 둘과 함께해야 가장 잘 이기고 RP를 많이 얻는가"**를 티어로 매겨 최상단에 보여준다.

## 핵심 시나리오

1. 내 실험체 / 무기를 고른다. 핵심 특성은 선택이다 (예: `에이든 / 양손검 / 액셀러레이터`).
2. 같은 팀이었던 **팀원 2명 조합**이 티어(S~D)별로 최상단에 표시된다.
3. 아래 상세 표에서 지표별로 정렬하고 비교한다.

## 집계 단위

| 대상 | 단위 |
|---|---|
| 내 실험체 | 실험체 / 무기 / 핵심 특성 (특성은 선택, 기본은 전체) |
| 팀원 2명 | 실험체 / 무기 × 2. 순서 무시 (A+B = B+A) |

## 지표 (조합별)

| 지표 | 정의 |
|---|---|
| 판수 | 내 실험체와 그 2명이 같은 팀이었던 경기 수 |
| 1위율 | 팀 최종 1위 비율 |
| TOP3율 | 팀 최종 3위 이내 비율 |
| 평균 RP | 해당 경기에서 **내 실험체**가 얻은 MMR 변화량의 평균 |
| 평균 순위 | 팀 최종 순위 평균 |

## 티어 산정

- **기본 기준은 종합 점수**: 1위율, TOP3율, 평균 RP, 판수(로그 스케일)를 정규화한 뒤 가중치를 둬서 합산한다. 가중치는 설정값 한 곳에서 관리한다.
- **기준 전환**: 승률 / RP / 판수 단일 기준으로 바꿀 수 있다.
- **티어 구간**: 점수 백분위로 자른다. 초안은 S 상위 10%, A 25%, B 50%, C 75%, 나머지 D.
- **최소 판수**: 기본 30판, 조절 가능. 미만인 조합은 티어에서 빼고 "표본 부족"에 따로 표시한다.

## 필터

- **시즌**
- **티어 구간 (누적 그룹)**: 다이아몬드 이상 / 메테오라이트 이상 / 미스릴 이상 / 상위 1000위. 단일 티어 대신 누적으로 묶어 표본을 확보한다.
- **내 실험체**: 실험체 / 무기 / 핵심 특성
- **최소 판수**
- **기준**: 종합 / 승률 / RP / 판수

## 화면 구성

```
[필터] 시즌 · 티어 구간 · 내 실험체(무기/특성) · 최소 판수
[기준] 종합 | 승률 | RP | 판수
─────────────────────────────
S │ 아야/권총 + 엘레나/레이피어   …
A │ …
B │ …
─────────────────────────────
[상세 표] 조합 · 판수 · 1위율 · TOP3율 · 평균 RP · 평균 순위 (열 클릭 정렬)
[표본 부족] 접힌 목록
```

## 상태와 데이터 흐름

- **Zustand**: 내 실험체 선택, 필터, 정렬 기준. URL 쿼리와 동기화해 링크로 공유할 수 있게 한다.
- **TanStack Query**: 필터 값을 쿼리 키로 써서 집계 API를 호출하고 캐싱한다.
- **서버 (Route Handler)**: DB에서 집계하고 티어를 계산한다. 응답에는 집계 결과만 담는다 (약관상 개인 식별 정보 비노출).

## 구현 순서 (가라데이터 단계)

1. **스키마**: 경기 / 참가자 / 메타 (실험체, 무기, 특성, 시즌)
2. **시드 스크립트**: 실험체 궁합에 편차를 준 가짜 경기 수만 판. 티어가 실제로 갈리는지 확인하는 용도
3. **집계·티어 계산**: 순수 함수로 분리
4. **집계 API**: Route Handler
5. **UI**: 디자인 방향을 정한 뒤 티어 보드 → 상세 표 → 필터 순서로 구현

## 결정 기록

| 결정 | 이유 |
|---|---|
| 팀원은 실험체/무기 단위 | 같은 실험체라도 무기에 따라 역할이 달라진다 |
| 특성은 내 실험체에만, 선택 필터로 | 같은 실험체/무기라도 특성(아이템)에 따라 전략이 달라진다. 팀원까지 적용하면 표본이 사라진다 |
| 표본 부족 대응은 일단 보류 | 실제 표본 규모는 수집해 봐야 안다. 부족하면 "팀원 무기 합치기" 토글을 추가한다 (구조상 저비용) |
| 누적 티어 그룹 | 단일 티어로는 상위 구간 표본이 너무 적다 |
| RP는 내 실험체 기준 | 목적이 "내가" 얻는 RP이기 때문이다 |
| 전적 분석 탭은 요청 시점에 Open API 호출 (예외) | 닉네임별 최근 20판은 미리 모을 수 없다. 전역 1.1초 큐·IP 제한·5분 메모리 캐시로 호출량을 막고, 수집기 실행 중에는 끈다 |
| 전적 분석의 식별 정보는 저장·전송하지 않음 | 닉네임·userId·결과는 DB·로그·URL·Claude 입력에서 뺀다. 조회 자체는 전적 사이트 선례를 근거로 사용자가 위험을 감수했다 (2026-10-26) |
| 시야 점수 = 시야 지표 4개(시야 기여·카메라 설치·카메라 제거·정찰 드론)를 DB 분포로 표준화해 평균 낸 50 ± 15 점수 | 단위가 달라 단순 합은 해석이 어렵다. 단순 합·표준화 평균·시야 기여 단독 모두 순위와의 상관이 비슷했다(−0.78~−0.80). 전적 분석 탭에서만 쓰고 조합 분석에는 넣지 않는다 (2026-10-26) |
| KDA = (평균 킬 + 평균 어시스트) / 평균 데스, 소견 입력에만 사용 | 판별 비율의 평균보다 데스가 적은 한 판에 덜 휘둘리고, 실험체 평균을 SQL 한 번으로 낼 수 있다. 화면에는 표시하지 않는다 (2026-10-26) |

## 미결 / 후보

- 종합 점수 가중치와 티어 백분위: 가라데이터로 결과를 보며 조정
- 시즌별 티어 경계 MMR: 키가 활성화된 뒤 실제 데이터로 확정
- API 필드명 (`bestWeapon`, `traitFirstCore`, `mmrGain` 계열): 가정. 실제 응답과 대조 필요
- 패치 버전 필터 (시즌보다 세밀함): 검토 후보
- 1위율 기준선 12.5% (8팀) 표시: 검토 후보
